Today, that entire pipeline has collapsed into a single morning of work.\n\nTwo tools Google Stitch and Claude Code have made it possible for anyone. You design your app in Stitch using plain English prompts, then copy or export the generated code and hand it to Claude Code, which builds out the full working app for you. No Figma skills, no manually writing CSS, no describing your design in words and hoping the AI gets it right.\n\nFor those who want to go further, an optional MCP (Model Context Protocol) connection lets Stitch talk to Claude Code directly so your design data flows in without any copypasting. But even without MCP, the core workflow is fast, free and suprisingly powerful.\n\nThis guide walks you through every step, even if you have never touched a design tool or AI coding assistant before.\n\n1. What are these tools, and why do they work so well together?\n\nGoogle Stitch\n\nGoogle Stitch is a free AI-powered UI design tool built by Google Labs. You describe what you want in plain english, and it generates a complete, high-fidelity interface screens, components, color palettes, and all powered by Google’s Gemini AI models.\n\nThe March 2026 update was a major leap forward. Stitch now features:\n\nAn AI-native infinite canvas where you can combine images, text, code and UI components side by side.\nGeneration of up to five screens simultaneously, instead of one at a time\nA built-in design agent that reasons across your entire project history\nInteractive prototyping — click “Play” to simulate your app’s user journey\nVoice commands for real-time design critiques and on-the-fly changes\nDESIGN.md — an agent friendly markdown file that exports your full design system (colors, typography, spacing, components) for use in other tools\n\nClaude Code\n\nClaude Code is Anthropic’s AI coding assistant that runs in your terminal. Unlike chat based coding tools, Claude Code operates directly inside your project — reading files, writing code, and executing commands autonomously. Give it a task and it handles the full implementation.\n\nIt is available with Claude.ai Pro plan ($20/month or higher)\n\nMCP: The Bridge Between Them\n\nMCP (Model Context Protocol) is an open standard that lets AI tools talk to each other through a shared interface. The stitch-mcp package acts as a bridge: it connects Claude Code directly to your Stitch project, letting Claude read your design data (layout, colors, HTML, screenshots) and implement it as real code — without any manual copy-pasting.\n\n2. Setting Up Claude Code + Stitch MCP\n\nThe setup has a few steps, but you only do this once. Here is a complete walkthrough.\n\nStep 1: Install Claude Code\n\nClaude Code requires Node.js (v18 or later). Install it from nodejs.org if you do not have it, then run\n\nnpm install -g @anthropic-ai/claude-code\n\nAuthenticate with your Anthropic account:\n\nclaude login\n\nStep 2: Get Your Stitch API Key\n\nThis is straightforward — no Google Cloud setup required.\n\nGo to stitch.withgoogle.com and sign in with your Google account\nOpen Settings (top-right corner)\nNavigate to the API Keys section and create a new key\nCopy the key and keep it somewhere safe\n\nStep 3: Connect Stitch to Claude Code\n\nRun this single command in your terminal, replacing YOUR-API-KEY with the key you just copied:\n\nclaude mcp add stitch --transport http https://stitch.googleapis.com/mcp --header \"X-Goog-Api-Key: YOUR-API-KEY\"\n\nThat is it. Claude Code registers the Stitch MCP server automatically — no config files to edit, no JSON to write.\n\n3. Designing in Google Stitch: Prompting for Great UI\n\nThe quality of what Stitch generates depends heavily on how you describe it. Most people get mediocre results because they type one vague sentence. Here is a framework that producrs production-quality designs consistently.\n\nThe 4-Part Prompt Formula\n\nPart 1: App Type + Platform\n\nStart by telling Stitch exactly what kind of interface you are building and where it will live.\n\nExample: “A mobile iOS app” or “A web dashboard” or “A SaaS onboarding flow”\n\nPart 2: Purpose + Target User\n\nExplain what the app does and who is using it. This shapes layout decisions, visual weight, and information density.\n\nExample: “for project managers who need to track team tasks at a glance”\n\nPart 3: Screen + Key Components\n\nList the specific screens and the components each screen needs. The more specific you are, the closer the first draft will be to what you want.\n\nExample: “Dashboard screen with KPI cards at the top, a line chart showing weekly activity, and a task list below. Sidebar navigation with Home, Projects, Team, and Settings”\n\nPart 4: Visual Style\n\nDescribe the aesthetic — color scheme, mood, reference apps. Stitch interprets style cues well.\n\nExample: “Dark theme, clean and minimal, inspired by Linear and Vercel Blue accent colors, monospace font for code snippets.”\n\nFull Example Prompt\n\nPutting it all together:\n\n\"A web SaaS dashboard for a project management tool used by\",\n\"software teams. I need three screens:\",\n\"\",\n\"1. Overview Dashboard: KPI cards (open tasks, completed today,\",\n\"   team velocity), a line chart for sprint progress, and a\",\n\"   recent activity feed.\",\n\"\",\n\"2. Task Board: Kanban columns (Backlog, In Progress, Review,\",\n\"   Done) with draggable task cards showing assignee avatar,\",\n\"   priority label, and due date.\",\n\"\",\n\"3. Settings Page: Profile section, notification preferences,\",\n\"   and team members table.\",\n\"\",\n\"Dark theme, minimal design. Sidebar navigation. Inspired by\",\n\"Linear. Blue and purple accent colors.\"\n\nIteration Tips\n\nStart broad, then drill down: Generate all screens first, then refine each one individually\nUse chat to tweak without regenerating: ‘Move the chart to the right side’ or ‘Make the sidebar narrower’ works without starting over\nUse the multi-select trick: Hold Shift, select multiple screens, and apply a single prompt to update all of them at once — great for theme changes\nVoice canvas: Speak your changes out loud. Say ‘give me three different color palettes for this screen’ and watch Stitch respond in real time\nGenerate the DESIGN.md file: Go to Export > DESIGN.md to create your design system file before connecting to Claude Code. This gives Claude the full context it needs\n4. Connecting Stitch to Claude Code via MCP\n\nOnce your design looks good in Stitch, the next step is getting Claude Code to implement it. There are two ways to do this — starting with the simpler one.\n\nPath A: Copy & Export (The Default Way)\n\nThis is the quickest path and requires no extra setup.\n\n5. In Stitch, open the screen you want to build\n\n6. Click the code panel on the right — Stitch shows you the generated HTML and CSS\n\n7. Copy the code, or use Export > DESIGN.md to get your full design system as a markdown file\n\n8. Open Claude Code in your project and paste it in:\n\n\"Here is the design code for my dashboard screen [paste code].\n Build this as a React component with Tailwind CSS.\"\n\nClaude reads the design and starts generating. For a landing page or simple screen, expect working code in a few minutes. You can also paste the DESIGN.md file to give Claude your full design system — colors, typography, spacing — so it stays consistent across every screen it builds.\n\nPath B: Direct MCP Connection (Advanced)\n\nIf you are building a multi-screen app and want a live connection between Stitch and Claude Code — so Claude can pull design data directly without any copy-pasting — MCP is the way to go. See Section 2 for the full setup. Once connected, you simply tell Claude:\n\nThe build_site Command: Scaffold an Entire App at Once\n\nFor multi-screen apps, the build_site tool maps your Stitch screens to routes and generates a deployable site structure:\n\nnpx @_davideast/stitch-mcp tool build_site -d '\n{\n  \"projectId\": \"YOUR_PROJECT_ID\",\n  \"routes\": [\n    { \"screenId\": \"abc123\", \"route\": \"/\" },\n    { \"screenId\": \"def456\", \"route\": \"/dashboard\" },\n    { \"screenId\": \"ghi789\", \"route\": \"/settings\" }\n  ]\n}'\n\nFind your screen IDs by running:\n\nnpx @_davideast/stitch-mcp view --project YOUR_PROJECT_ID\n5. Workflow & Iteration: From Design to Deployed Code\n\nHere is the end-to-end workflow that gets you from blank canvas to working app.\n\nThe Full Workflow\n\nGet Ebubechukwu Ugbor’s stories in your inbox\n\nJoin Medium for free to get updates from this writer.\n\nSubscribe\n\nRemember me for faster sign in\n\nPhase 1: Design (20–40 minutes)\n\nOpen stitch.withgoogle.com\nChoose Experimental Mode for your first pass\nUse the 4-part prompt formula to describe your app\nReview the generated screens — compare multiple variants\nRefine with follow-up prompts or voice commands\nUse the multi-screen generator to create all your key screens\nClick ‘Play’ to preview your interactive prototype\nExport DESIGN.md from the canvas\n\nPhase 2: Implementation (20–30 minutes)\n\nIn Stitch, open each screen and copy the generated code from the code panel\nExport DESIGN.md for your full design system (colors, fonts, spacing)\nOpen Claude Code in your project directory\nPaste the code and instruct Claude: ‘Build the dashboard screen as a React component using this design code’\nReview Claude’s output in your browser\nUse Claude to fix specifics: ‘The nav sidebar is too wide, reduce it to 240px’\n(Optional) Set up MCP for a live connection if you want Claude to pull updates automatically\n\nPhase 3: Polish (10–20 minutes)\n\nSwap placeholder images for real ones\nAdd hover states and transitions (Stitch designs are static — interactions need to be specified)\nCheck spacing and padding in the browser — AI often gets these close but not exact\nTest on mobile if targeting responsive layouts\n\nTotal time from blank canvas to a working, shareable prototype: 60–90 minutes. A year ago, the same work took a designer half a day and a developer a full day.\n\nWhat Claude Code Does Well\n\nReading complex design specs and translating them into clean component code\nMaintaining design consistency across multiple screens using the DESIGN.md context\nGenerating TypeScript types for data structures implied by the UI\nWiring up routing between screens\nAdapting Stitch’s HTML/CSS output into React + Tailwind patterns\n\nWhat Still Needs Human Judgement\n\nSpacing tweaks — AI gets padding and margins close, but pixel-perfect polish requires manual review\nPlaceholder content — replace generated text and images with real content\nComplex animations and micro-interactions\nAccessibility audit — add proper ARIA labels and keyboard navigation\nBrand alignment — Stitch’s color choices may not match your exact brand tokens\n6. Real Examples\n\nExample 1: SaaS Landing Page\n\nPrompt used in Stitch:\n\n“Landing page for an AI writing assistant called InkFlow.\n\nWeb, modern SaaS aesthetic. Clean white background,\n\npurple and indigo accents.\n\nSections: Hero (headline, subheadline, CTA button, product\n\nscreenshot mockup), Features (3 cards with icons), Social\n\nproof (3 customer quotes with avatars), Pricing (2 tiers,\n\nmonthly/annual toggle), Footer with links.”\n\nWhat Stitch generated: Four complete screen variants in under 30 seconds. The hero section had a clean headline layout with a visible product screenshot area, the feature cards used a consistent icon style, and the pricing section correctly rendered the two-tier structure.\n\nClaude Code instruction after connecting via MCP:\n\n“Implement the first landing page variant as a Next.js page\n\ncomponent with Tailwind CSS. Use the InkFlow project color\n\ntokens from DESIGN.md.”\n\nResult: A deployable Next.js page in approximately 12 minutes of generation time.\n\nExample 2: Mobile Dashboard\n\nPrompt used in Stitch:\n\n“Mobile iOS app dashboard for a personal finance tracker.\n\nDark theme, minimal. Shows monthly spending by category\n\nas a donut chart, recent transactions list, and quick\n\naction buttons (Add Expense, Transfer, Pay). Bottom tab\n\nnavigation: Home, Budget, Cards, Profile.”\n\nWhat Stitch generated: A complete dark-mode mobile layout with a clean donut chart placeholder, well-spaced transaction rows, and a bottom tab bar with correct spacing for iOS.\n\nCommon issues and fixes:\n\nChart type: Stitch generated a pie chart instead of a donut. Fix: ‘Change the portfolio chart to a donut chart with a centered total amount label’\nNavigation label alignment: Tab labels were centered but not aligned below icons. Fix: ‘Align each tab label directly below its icon with 4px gap’\n7. Troubleshooting Common Issues\n\nMCP connection not working\n\nRun npx @_davideast/stitch-mcp doctor — verbose to diagnose\nDouble-check your STITCH_API_KEY is set correctly — regenerate it in Stitch Settings if needed\nRestart Claude Code after updating your MCP config\n\nStitch output quality is low\n\nSwitch to Experimental Mode (Gemini 2.5 Pro) for better results\nAdd more specific detail to your prompt — vague prompts produce generic layouts\nUpload a reference screenshot or sketch if you have one — Stitch uses it as visual context\n\nClaude is not matching the design accurately\n\nMake sure you exported and shared the DESIGN.md file with Claude\nUse get_screen_image to give Claude a screenshot of the screen: ‘Look at the screenshot for screen abc123 and match it closely’\nBe specific about the tech stack: ‘React with Tailwind CSS, not inline styles’\n\nFinal Thoughts\n\nThe Stitch + Claude Code + MCP workflow is one of the most significant shifts in how software gets built. For teams, it changes the role of the designer from pixel-pusher to creative director: prompt, review, and refine — rather than manually constructing every component.\n\nThe best way to understand it is to use it.
